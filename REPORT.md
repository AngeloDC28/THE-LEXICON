# THE LEXICON — Maintainability Report

Current state of the project as of May 2026. All original recommendations from the previous report have been implemented. This document reflects the actual state, what's still rough, and what to tackle next.

---

## 1. What got fixed

Everything in the original report has shipped. In order:

### 1.1 ✅ Parse + duplicate-import scan (`npm run check`)
`node --check` runs on all `.js`/`.mjs` files. A second pass detects duplicate top-level `import { x } from 'y'` within the same file. Both bugs that broke the original site (duplicate import in `search-engine.js`, unescaped quote in `translations.js`) are now caught before they can reach main.

### 1.2 ✅ GitHub Actions CI
`.github/workflows/check.yml` runs on every push to `main` and every PR. It blocks merge if:
- Any JS file fails to parse
- A duplicate import exists
- An entry JSON fails schema validation
- Any `images[].src` references a file not on disk
- `database.js` is out of sync with `content/entries/`
- `translations.js` is out of sync with `content/translations/`
- `en.json` has empty or null values

### 1.3 ✅ Per-entry JSON files
`database.js` is now auto-generated by `.github/scripts/build-data.mjs` from `content/entries/<id>.json`. The JS file is committed so GitHub Pages can serve it without a build step, but it is never edited by hand. Adding entry #16: create one JSON file, add its id to `content/order.json`, run `npm run build-data`.

### 1.4 ✅ JSON schema + zero-dependency validator
`content/entry.schema.json` defines the required shape. `validate-entries.mjs` implements a zero-dep validator (no `ajv`, no `node_modules`) covering: type, required, properties, additionalProperties, items, minItems, minLength, minimum, maximum, pattern, enum, `$ref`. A malformed entry fails CI with a precise field-level error.

### 1.5 ✅ Asset existence check
`check-assets.mjs` walks `public/THE-LEXICON-ASSETS/` and cross-references every `images[].src` in every entry JSON. Missing files are hard failures. Orphan files on disk (unreferenced) are warnings.

### 1.6 ✅ Redundant fields removed
`imageUrl` (always duplicated `images[0].src`) and top-level `hotspots: []` (always empty — real hotspots live inside each image object) have been removed from all entries and from the schema. `additionalProperties: false` prevents them from creeping back.

### 1.7 ✅ Per-language translation files
`translations.js` is now auto-generated by `.github/scripts/build-translations.mjs` from `content/translations/<lang>.json`. The source of truth is the JSON files. `validate-translations.mjs` fails CI if `en.json` has empty values and warns on cross-language key drift. To update a translation: edit the `.json` file, run `npm run build-translations`, commit both.

## 2. What's still rough

Known issues in the current codebase, in order of practical impact:

### 2.1 Translation drift (13 active warnings)
All non-English language files are missing between 29 and 48 keys that exist in `en.json`. The runtime falls back to English for missing keys — nothing breaks — but the intended multilingual experience degrades silently. The missing keys are mostly the newer taxonomy labels (`tax_brand`, `tax_era`, etc.) and note field labels (`note_critique`, `note_strategy`, `note_provenance`).

`zh.json` and `ja.json` also have 5 extra keys each (`Gucci`, `Prada`, `Maison Margiela`, etc.) that no longer exist in `en.json` — leftover from an earlier taxonomy iteration.

**Fix**: add the missing keys to each language file. The English fallback text is already in `en.json`; pasting it as a placeholder keeps CI clean while awaiting proper translation.

### 2.2 Orphan NOTES.md files (16 files, no broken references)
Each entry folder in `public/THE-LEXICON-ASSETS/` contains a `NOTES.md` with editorial research notes. These aren't referenced by any entry JSON, so `check-assets.mjs` flags them as orphans (warnings, not failures). They don't break anything but they're accumulating in the asset directory.

**Fix**: either incorporate the notes content into the `notes.critique` / `notes.strategy` / `notes.provenance` fields of each entry JSON (where they belong), then delete the `.md` files; or move them to `content/entries/` as sidecar files outside the asset directory. The first option is better — it keeps all structured content in one place.

### 2.3 Image layout shift (no explicit dimensions)
No `<img>` tag in the detail view carries explicit `width` and `height` attributes. Browsers reserve zero height for the image until it loads, then reflow — a CLS (Cumulative Layout Shift) hit that Google PageSpeed flags. This is benign for a private research tool but would matter if the site were optimised for public discovery.

**Fix**: add a `dimensions: { w, h }` field to each image object in the entry JSON, populated by a one-time measurement script. The render code then sets `width` and `height` on the `<img>` tag.

### 2.4 `fix-all.js` is dead weight
`.github/scripts/fix-all.js` was a one-off migration script that mutated `translations.js` by string-replace to inject Angelo's name into the About text. Now that:
- `translations.js` is auto-generated and would overwrite those mutations
- Angelo's name already lives correctly in `en.json → modal_about_body`

...the script does nothing useful. It has been removed from `prebuild` but the file still exists on disk. It can be deleted.

### 2.5 No image optimisation
Images ship at their source resolution and encoding. A 3MB JPG costs the same to serve as a 200KB WebP. At 15 entries × ~15 images each, the unoptimised total is significant on mobile.

**Fix**: a single `sharp` script in prebuild — resize to max 2400px wide, convert to WebP, write a `.dimensions.json` sidecar. Low effort, high impact on mobile load time.

## 3. The "add a new entry" workflow

```bash
# 1. Create a branch
git checkout -b entry/galliano-dior-aw00

# 2. Drop images into the right folder
mkdir public/THE-LEXICON-ASSETS/galliano-dior-aw00
# copy galliano-dior-aw00-{01..N}.jpg into that folder

# 3. Create the entry JSON from the template
cp content/entries/_template.json content/entries/galliano-dior-aw00.json
# fill in all fields

# 4. Register in the display order
# add "galliano-dior-aw00" to content/order.json at the desired position

# 5. Rebuild artifacts
npm run build-data

# 6. Validate locally (catches schema errors, broken asset paths)
npm run check

# 7. Visual check
python -m http.server 8765     # or any static server; no node_modules needed

# 8. Push + open PR
git push -u origin entry/galliano-dior-aw00
gh pr create --title "entry: Galliano for Dior AW00"
```

CI runs all checks automatically. The PR is blocked from merging if anything fails.

## 5. What NOT to change

- **No framework.** Vanilla ES modules + Tailwind CDN loads in under 1 second. Framework overhead is not justified at this scale.
- **No CMS.** Git-as-database is more durable and faster to query than any hosted CMS for under 100 entries.
- **No ESLint/Prettier yet.** The `npm run check` script catches the bugs that have actually bitten this project. Config bikeshedding is not worth it until there are multiple active contributors.
- **No bundler for now.** GitHub Pages serves ES modules natively. A Vite build step only becomes necessary when you need tree-shaking or code splitting — not yet relevant.
